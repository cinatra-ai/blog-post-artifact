## Directory Purposes

**`src/`:**
- Purpose: TypeScript source — the only TypeScript in the repo.
- Contains: One file (`index.ts`) exporting the `SemanticArtifactManifest` constant.
- Key files: `src/index.ts`

**`skills/`:**
- Purpose: Cinatra skill definitions consumed by the LLM skill runner.
- Contains: One subdirectory per skill, each with a `SKILL.md` prompt file.
- Key files: `skills/blog-post-matcher/SKILL.md`

**`.github/workflows/`:**
- Purpose: GitHub Actions CI/CD pipelines for the extracted extension repo.
- Contains: `ci.yml` (build + kind gates), `release.yml` (publish).
- Key files: `.github/workflows/ci.yml`

## Key File Locations

**Entry Points:**
- `src/index.ts`: Package entry point; exports `blogPostArtifactManifest`. Declared as both `main` and `types` in `package.json`.

**Configuration:**
- `package.json`: Cinatra `apiVersion`/`kind`/`artifact` metadata block; peer dependency declarations.
- `tsconfig.json`: TypeScript compiler config; `rootDir=src`, `outDir=dist`, `module=ESNext`, `moduleResolution=bundler`.
- `.npmrc`: npm registry configuration (existence noted; contents not read).

**Core Logic:**
- `src/index.ts`: Entire imperative surface — one `const` export.
- `skills/blog-post-matcher/SKILL.md`: All classification logic (LLM prompt).

**CI:**
- `.github/workflows/ci.yml`: Dependency-shape gate, typecheck, test, pack dry-run, kind-specific gates.

## Naming Conventions

**Files:**
- TypeScript sources: `camelCase.ts` (only one file: `index.ts`).
- Skill prompts: `SKILL.md` (uppercase, fixed name per skill directory).
- Workflow files: `kebab-case.yml`.

**Directories:**
- Skill directories: `kebab-case` matching the skill's logical name (e.g., `blog-post-matcher`).

**Exports:**
- Manifest constant: `<artifactKind>ArtifactManifest` (e.g., `blogPostArtifactManifest`).

**Package name:**
- Pattern: `@cinatra-ai/<artifact-kind>-artifact` (e.g., `@cinatra-ai/blog-post-artifact`).

**Skill reference:**
- Pattern: `@cinatra-ai/<artifact-kind>-artifact:<skill-name>` (e.g., `@cinatra-ai/blog-post-artifact:blog-post-matcher`).

## Where to Add New Code

**New skill (additional classifier):**
- Create `skills/<skill-name>/SKILL.md` with front matter (`name`, `description`) and LLM instructions + JSON output contract.
- Reference the new skill in `src/index.ts` under `skills.matchers`.

**Change classification logic:**
- Edit `skills/blog-post-matcher/SKILL.md` — do NOT add TypeScript logic to `src/index.ts`.

**Change accepted MIME types or threshold:**
- Edit the `accepts` or `matcherConfidenceThreshold` fields in `src/index.ts` and mirror the change in the `cinatra.artifact` block of `package.json`.

**New TypeScript utility:**
- Place under `src/` (e.g., `src/helpers.ts`). The tsconfig `include` covers `src/**/*.ts`.

## Special Directories

**`dist/`:**
- Purpose: TypeScript compiler output (declarations + JS).
- Generated: Yes (by `tsc`).
- Committed: No (not present in tracked files).

**`.planning/`:**
- Purpose: GSD planning documents generated by codebase mapping tools.
- Generated: Yes.
- Committed: Project-dependent (not in `.gitignore` by default).
